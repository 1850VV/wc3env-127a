# 六步兵十字包围 MVP

左侧1级大法师带6个步兵，右侧1个农民持续向右移动。双方均用1.27a原生属性；不修改移速、碰撞、生命，不暂停农民，不借助地图边界。

```powershell
.venv/Scripts/python -m tools.kiting_prepare
.venv/Scripts/python -m tools.surround_mvp --visible --out runs/surround-mvp/watch
```

地图复用纯Python生成的开放平地。控制策略在 `tools/surround_policy.py`，实机验收在 `tools/surround_mvp.py`。此前风筝MVP的代码与结果保留。

## 控制策略

1. 固定分配前、后、上、下四个主位，另两名步兵为前侧翼补位。
2. 用己方视野中的农民坐标变化估计速度；步兵以270移速预测截击190移速的农民，分路超车。
3. 前方步兵到位后固定包围中心，再让四个主位向中心收紧。收口时目的地不再跟农民一起移动，避免全队只是在追赶。
4. 农民四周有步兵、且连续2秒仍在向右移动却被限制在35坐标半径内，才认定包围成功。
5. 保持围圈约3秒，不下攻击命令。大法师跟在约850坐标距离之后，不参与堵路。定期移动指令维持站位并抑制步兵自行攻击，让结果展示的是活体包围。

每50 ms游戏时间采样，每150 ms左右更新步兵命令。不是墙钟20 Hz性能承诺。策略只读取己方可见敌人；敌方私有观测仅用于独立验收。

几何方向覆盖只是候选包围，不能单独证明碰撞已闭合。日志中的 `conservative_circle_sealed` 是基于简化圆形碰撞的保守诊断；引擎实际路径和碰撞以持续移动命令下的位移为准，不能把这个诊断当成实机验收结果。

## 已验证结果（2026-09-27）

- 种子42和43均成功；另录制一轮种子42，结果一致。
- 7.40秒进入十字收口，9.80秒完成受阻确认，12.80秒结束演示。
- 农民仍是220/220 HP；6/6步兵存活；农民仍在执行向 `(3100,0)` 的移动命令。
- 连续受阻观测5.05秒；确认后的约3秒净位移约4.3，活动范围约1.7×11.8。
- 最后位置约 `(721.5,32.6)`，远离目标点和地图边界。零拒绝动作。
- 116项环境单测（含5项策略检查）、156项Agent单测通过；Ruff lint/format通过。

原始证据在 `runs/surround-mvp/demo/result.json` 和 `trace.json`。这是固定平地、向右逃跑、6兵齐全的MVP；不声称障碍寻路、农民主动变向、步兵损失后重分配或对抗其他玩家已经验证。

## 录制

```powershell
.venv/Scripts/python -m tools.surround_mvp --visible --record --ready-wait 15 --out runs/surround-mvp/demo
```

需 `pillow mss numpy imageio[ffmpeg]`。等待期间将游戏置前，保持不被其他窗口遮挡。MP4以10fps对应每100ms游戏时间，末尾额外保留2秒结果画面。单位通过debug spawn准备，因此不把原生w3g录像视为此场景的复现依据。
